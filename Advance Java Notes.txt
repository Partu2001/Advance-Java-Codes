1. SERIALIZABLE (Interface) :
-Serializable is a marker interface from Java.
-It allows the serviet object to be converted into bytes.
*Why is this needed?
-Servlet container may:
  Save servlet state
  Transfer serviet between servers
  Support session replication
-GenericServlet implements Serializable so servlet can be safely managed by the container. 

2. SERVLET (Interface) :
-This is the core interface of Serviet API
-It defines the life cycle of a servlet
* Important methods:
-init() called once
-service() handles requests
-destroy() called once before removal
-getServletConfig()
-getServletinfo()
Any class that wants to become a servlet must follow this interface.

3. SERVLETCONFIGURATION (Interface) :
-Used to pass initialization parameters to a sviet.
-Parameters are defined in web.xml or annotations.
* Key points :
-Works for one servlet only
-Used inside ide init()

4. GENERICSERVLET (Abstract Class) :
-GenericServlet is the bridge between inters and real servlets.
-It:
 Implements Servlet
 Implements ServletConfig
 Implements Serializable
* Why GenericServlet is important?
-Removes complexity
-Provides ready-made implementations
-Developer only needs to override service() method
* Key features:
-Protocol independent
-Does not care if request is HTTP, FTP, etc.
-Mostly used for learning, not real projects.

5. HTTPSERVLET (Abstract Class) :
-HttpServlet extends GenericServlet
-Specially designed for HTTP protocol
-This is the MOST USED class in real projects.
* It provides:
-doGet()→ GET request
-doPost() → POST request
-doPut()
-doDelete()

** SESSION :
-To provide implementation for a complex requirement multiple request from user are required.
-Entire interaction is called as a Session.
 A session starts from the first user request still the application is closed(Implicity or Explicity).
-The intermediate data generated as a part of the request processing needs to be maintained for seamless execution.

* WHY SESSION TRACKING :
-Web application work on HTTP.
-HTTP is stateless protocol.
 Client state and execution history is not maintained.
-Dynamic application are bulit on the assumption that the same client access the application multiple times.
-Client data is lost with every request being considered as a new request.
-For a truly responsive application - the client data to be  maintained at the server side  for client identification.
-As HTTP does not provide any tools or utilities.
 Programmer to take care of identifying the client programmatically over the duration of a clients application access(a session).
-There is need to track the user activity across the entire session.
 This mechanism is called as session tracking.

* WHAT IS HTTPSESSION :
-HttpSession is an object provided to perform session tracking.
-Provides ease-of-programming to the developer by combining user identification and state management into a single object.

* HTTP SESSION OBJECT :
-This object created by the container.
-Saves information such as session id,creation time and last accessed time.
-Has default timeout value is 30 min.
-User information stored into the session object by using setAtrribute () method.
 Later when needed this information can be fetched from the session.

** INTRODUCTION TO JAVA SERVER PAGES (JSP) :
-Java server pages is technology that generates dynamic web pages based on HTML.

 ** JSP LIFE CYCLE :
It is divided into 7 phases :
1.Translation
2.Compilation
3.Loading
4.Instatiation
5.Initialization
6.Service
7.Destruction

1.Translation : The JSP is translated into servlet source code.
2.Compilation : The servlet source code is compiled into java byte code.
3.Loading class : The application loads the servlet class into memory using the application classLoader.
4.Instantiation : The application instantiates an instance of the servlet class for each JSP in the application.
5.Initailization : The jspInit () method is called on the instance to initialize it.
6.Service : The jspService method is invoked for each request recieved for the JSP.
7.Destruction : The servlet instance is taken out of service jspDestroy () method called.

** HIBERNATE QUERY LANGUAGE (HQL) :
*Bulk Oprations in Hibernate :
-To perform bulk operations,we can use one of the following techniques.

** HQL :
-HQL queries are easy to learn because HQL looks like SQL only.
-HQL queries are also called as Object Oriented form of SQL queries.
-We can easily translate the SQL commands into HQL commands by replacing the table name with POJO class names and column name with POJO property name.
-At runtime hibernate will convert the HQL query into SQL query according to database.

-IN HQL we can divide the select operations into 2 types :
1.Reading Complete Entity using from clause.
2.Reading Partial Entity using select clause.

1.Reading Complete Entity (from clause) :
-In HQL selecting the all the columns is called reading a complete entity.
Ex:
 SQL : select * from emp;
 HQL : from emp e;
-HQL commands to read a complete entity are directly begins with "from " keyword.

2.Reading Complete Entity (select clause) :
-In hibernate reading a specific columns is called reading partial entity or entities.
Ex:
 SQL : select id,name,salary from emp;
 HQL : select e.id,e.name from emp e;

** Parameter Binding in Hibernate :
There is two types of parameter binding in the HQL 
1.Positional Parameter  :
  Query q =session.createQuery("from employee e where e.salary between ? and  ?");
  q.setParameter(0,minSal);
  q.setParameter(1,maxSal);

2.Name Parameter :
   Query query8=session.createQuery("from EmpTable where id=:id");
   query8.setParameter("id", 2);
   EmpTable e7= (EmpTable) query8.uniqueResult();
   System.out.println(e7);

** COMPONENT MAPPING :
* Creating Persistent Classes :
-The entire concept of Hibernate is take the value from java class attribute and persist them to a database table.
-A mapping document helps Hibernate in determining how to pull the values from the classes and map them with table and associated fields.
-Java classes whose objects or instance will be stored in database tables are called persistent classes in Hibernate. 


* Creating Persistent Class :
-Hibernate supports following three most important mapping
 has-a - Component Mapping
 is-a - Inheritance Mapping
 Mapping of associations between entity classes.

** Component Mapping :
-Entity class can have a reference to another class as a member variable.
-A component mapping is mapping for a class having a refernce to another class as a member variable.
-Only single table is enough which holds the information of all the attributes of both classes.
-@Embedded is used to embed a type into another entity.
-@Embeddable  annotationcto declare that a class will be embedded by other entites.
-Both annotations need to be used together to map has-a kind of class relationship.

   Employee  ===>  has-a  ===> Address

** INHERITANCE MAPPING :
-Relational databses dont have striaghtforword way to map class hirarchies onto database tables.
-To address this the JSP spcification provides several strategies: 
 Table Per Hierarchy
 Table Per Concrete Class
 Table Per Subclass
-Each strategy results in a different database structure.

Following annotations are used this mapping :
 @Inheritance(strategy  = InheritanceType.SINGLE_TABLE)
  The single cTable stratergy creates ine table for the entire class hirarchy

 @DiscriminatorColumn and @DiscriminatorValue
   The extra column details are provided using @@DiscriminatorColumn
   The discriminator value is used to define the each row/record

* INHERITANCE MAPPING TABLE PER HIERARCHY :

1.The get() method is primarily used for eager loading, meaning it attempts to fetch the actual data immediately. 
Database Hit: It immediately hits the database (if the object is not already in the session cache) to retrieve a fully initialized object.
Missing Data: If no record exists for the given primary key, it returns null.
Return Type: Returns the actual persistent entity or null.
Best Use Case: Use get() when you are not certain if the object exists in the database and want to perform a null check before proceeding. 

2. load() Method
The load() method is designed for lazy loading to improve performance by delaying database access. 
Database Hit: It does not hit the database immediately. Instead, it returns a proxy object—a placeholder that only contains the identifier. The actual database query is triggered only when you access a property of the object other than its ID.
Missing Data: If the record does not exist, it will throw an ObjectNotFoundException (specifically org.hibernate.ObjectNotFoundException) when you attempt to access its properties.
Return Type: Returns a proxy object (a dynamic subclass of the entity).
Best Use Case: Use load() when you are certain the record exists, or when you only need a reference to the object (e.g., to set a foreign key relationship in another entity) without needing its full data.

** TRANSACTION :
-A transaction is a group of operations that are executed as one single unit of work.
 Either all operations succed
 Or all operations fail
-The system moves from :
 One consistent state -> another consistent state
Ex:
 Money transfer from Account A to Account B
 Debit+Credit =one transaction

* ACID PROPERTIES :
-ACID ensures that transactions are safe and reliable.
A-AUTOMACITY :
-Means "all or nothing".
-Either all operations are performed or none.
Ex : If debit happens but credit fails -> rollback debit

C-CONSISTENCY :
-After transaction data must follow business rules.
-Database should never be left in an invalid
Ex : Account balance should never become negavtive

I-ISLOATION :
-Multiple transactions should be not affect each other
-Each transaction behaves as if it is the only one running.
Ex : Two users updating same record  should not corrupt data.

D-DURABILITY :
-Once transaction is committed data is permanent
-Data survives :
 System crash
 Power failure

** Spring Transaction Attributes :
-Transaction attributes define how a transaction should behave.
-They are mainly used in declarative transactions.

* Important Transaction Attributes : 
1.Propagation Behavior :
-Defines how transactions are created or joined.
-Controls transaction boundaries.

2.Isolation Level :
-Defines how transaction ontract with each other.
-Controls concurrent data access.

3.Read-Only :
-Indicates transaction is only for reading data.
-Helps performance optimization.

4.Timeout :
-Maximum time  a transaction can run.
-If exceeded -> transaction is rollback automatically.

5.RollBack Rules :
-Defines when transaction should rollback.
-Can rollback are : 
 Runtime exception
 Checked exception

** Transaction Propagation Behavior :
-It defines how a method should behave with transaction when it is called.
1.Propagation_Required :
-Default behavior
-Uses existing transaction if present
-Otherwise starts a new transaction
Most commonly used

2.Propagation_Mandatory :
-Method must run inside a transaction.
-If no transaction exists -> exception
Used when transaction is compulsaory.

3.Propagation_Required_New :
-Always starts new transaction.
-Existing transaction is suspended.
Independent transaction.

4.Propagation_Nested :
-Runs inside a nested transaction
-Can commit or rollback independently
-If no transaction exists -> behaves like Required
Uses Savepoints

5.Propagation_Supports :
-Uses transaction if available
-Otherwise runs without transaction.
Optional transaction support.

6.Propagation_Not_Support :
-Runs without transaction
-Existing transaction is suspended.
Non-transactional logic

** Transaction Isolation Levels :
Isolation  controls how transactions affect each other.

1.Isloation_Default :
-Uses databases default isolation levels.

2.Isloation_Read_Incommitted :
-Can reed uncommitted data
-Allow dirty reads
Not least safe

3.Isloation_Read_Committed :
-Read only committed data
-Prevents dirty reads
Commonly used

4.Isloation_Repeatable_Read :
-Same data read multiple times give same result.
-Prevents dirty+not repeatable reads.

5.Isloation_Serializable :
-Highest isloation level.
-Prevents all read problem.
-Uses full table locks
Slow but safest.
